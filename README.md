# Anchor 0.4.0 — offline Android personal planner

Native Android app for HONOR Magic4 Lite 5G, Android 8+ / arm64. No account, Internet permission, Google Calendar, server, analytics or cloud backup. App-private SQLite holds calendar/tasks, explicit memories and chat.

## What works
- Today timeline, own month calendar, add/edit/delete/check tasks and protected events.
- Explicit fixed/flexible flag. Deterministic gap placement, whole task duration, protected/active commitments, day window and flexible-work percentage cap. Overload stays unscheduled.
- Event observation after edits/completion/app open/clock changes, plus deferrable WorkManager checks at minimum 15-minute intervals. Android/OEM power management may delay them. LLM inference never runs periodically.
- Durable change reports and revision-checked, all-or-nothing Undo. Successful Undo pauses automatic planning until re-enabled.
- AlarmManager reminders, optional bounded ringing, 5/10-minute snooze and dismiss. Snooze changes the alarm only. Exact access and visible notification controls are needed for ringing. Force stop prevents delivery until reopen.
- Editable 60-day challenge start, actual completion-day heatmap and streak; missed days do not reset the challenge.
- Clear single-task chat requests save real calendar entries and return a confirmation, a timeline link and guarded Undo. Defaults: 30 minutes, next upcoming requested local time, protected/fixed. Weekdays are supported. Complex model interpretations open an editable review form; machine JSON stays internal. Conflicts and duplicates do not overwrite existing work.
- Repeating chat requests open the routine builder. Routines & goals: suggested chores/reading/work, custom titles and durations, selected weekdays, 1–90 calendar days (30/60/90 shortcuts), free-slot preview using your day window/allocation, actual daily tasks and optional reminders. Full days retain visible untimed tasks that can be planned later. Stop upcoming sessions preserves past, completed and individually edited work.
- Period plans arrange up to 12 daily essentials and challenge goals over one 1–90-day range, sharing one free-time budget. Includes editable suggestions for your reading topics, library, rest, hackathons, research and chores. November–December 2026 is 61 days. Review every session, save the batch together, and use guarded batch Undo. Occasional events need their own dates.
- Chat can open an editable plan from a task list, or a selection/review for moving a particular flexible session. Protected commitments cannot move through this tool. Moves check conflicts and stale edits and have change-report Undo. `/plans` lists saved plan summaries and active routines.
- Daily focus names the next incomplete entry. Daily and weekly bars and the 60-day map use equal task shares: green completed, red overdue, neutral not yet due. Events do not inflate progress; empty days stay neutral. Late completion turns its share green.
- Offline GGUF text chat through bundled llama.cpp CPU JNI. Model import, stop/unload, real device benchmark/export. Explicit local commands: /help, /today, /tomorrow, /progress, /replan, /reports, /undo ID, /complete ID, /remember NOTE. Model replies open a review form rather than directly writing the calendar.
- On-demand Android on-device recognition and installed offline English TTS. Availability is checked; no online recognizer fallback. Voice stops on leaving the activity; queued stale transcripts are discarded. Saved-memory context can be disabled.

## Use
Install the developer-signed APK on the phone. In Settings enable notification/exact alarm access and opt into ringing if desired. Use Today → Routines & goals → + New routine to choose a suggestion, weekday pattern and period; Preview shows every proposed session before Save. Nothing is seeded automatically. Add a timed task with a reminder; fixed tasks/events keep their times. Mark only movable work Flexible. Edit your day window and allocation in Settings. Check reports after rearrangement; Undo also pauses automatic planning. Set the challenge start date in Progress. Task-share colours belong to the task’s planned date; activity totals/streaks count actual completion dates. A timed task is overdue once its full duration ends; an untimed task becomes overdue after its day ends. A later completion corrects the red share.

The nearest 200 pending alarms are armed at once and refilled after reminder delivery, on calendar checks and on reboot/clock changes. Snoozes retain their own due time. Android alarm scheduling failures are shown in Settings. This bounds system alarm use when several 90-day routines exist.

Import one official supported Q4_K_M GGUF through Settings. A model is a separate file and is not included in the APK/source archive. Start with measured device results in the delivered validation report. System voice requires an installed on-device service/voice; microphone access is requested when used. Typing works independently.

For the new period builder, open Today → Period plans · daily & challenges → New plan. Add the interests template and optional household chores, adjust titles/minutes/weekdays, choose the period, then Preview plan → Save plan. Times are chosen from free slots inside your planning window. No-room sessions stay visible as Anytime work and have no alarm until timed. Existing notification/ringing settings apply.

For chat, try `Organize these tasks: reading, daily rest, research` or `Move #12 to tomorrow at 17:00`. The model proposes grouping only; deterministic rules choose slots. Long lists bypass inference rather than losing their tail. Recoverable model errors use editable list suggestions; the complete original request remains in the composer. The new live model-planning check reported a process crash before USB disconnected; the cause and final phone UI remain unverified. An OS/native process crash cannot be caught by the fallback. See docs/validation-report-0.4.0.md before treating this personal test build as validated.

## Build
Requirements: JDK17/21, Android SDK36, Gradle8.14.3. Run `./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`. APK: app/build/outputs/apk/debug/app-debug.apk. Test runner: android.test.InstrumentationTestRunner. Most instrumentation tests use disposable databases and do not alter calendar data. `AlarmLiveDeviceTest` explicitly creates/cleans one labeled real task and briefly rings. `CandidateBenchmarkDeviceTest` only loads an explicitly staged model; normal runs with no staged config do not load weights. `PlanModelDeviceTest` requires `-e run_plan_model true` and uses the already imported model with synthetic input.

A compiled arm64 runtime is included. To rebuild: set ANDROID_NDK_HOME=r28c and run scripts/build-native.sh; it fetches pinned llama.cpp d05706b4f32a545814856e98ca518292585443b9, uses CPU only and 16KB-aligned libraries. Additional licenses are under licenses/ and docs/.

## Implementation choice and limits
The recovered Work project already used Java framework views and SQLiteOpenHelper. This continuation preserves it and adds schema5 migrations from earlier supported versions. Kotlin/Compose, Room and DataStore remain a future migration, not implemented features. List interpretation is bounded and reviewed; arbitrary discussion planning, automatic book chapter division and whole-series conversational edits are not implemented. Individual sessions can be edited; changing the whole series means stopping future sessions and creating a new routine. Unsaved period/move dialogs do not yet survive activity recreation, so finish or cancel before rotating/leaving. The model adapter supports plain-text chat; LFM3 uses vendor nonthinking formatting, not tools/multimodal input. Small model reliability is evaluated separately from speed; deterministic planner rules enforce calendar safety. No always-on LLM, continuous microphone, cross-device sync, or guarantee against Android force stop/OEM restrictions. Data has Android sandbox/device encryption, with no separate database password encryption.
