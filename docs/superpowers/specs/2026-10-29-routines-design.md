# Recurring routines and honest daily progress

The user wants to describe chores or a goal once and receive real daily calendar entries over 30, 60 or 90 days. They chose automatic free-time placement with later manual adjustment. Each task completion should fill part of its scheduled day green; missed work fills red; future work stays neutral.

Retain the recovered Java/SQLite/native-alarm app. A routine has a title, first date, 1–90 calendar days, selected weekdays, session minutes and an optional start-time notification. Presets suggest reading, dishes, sweeping, laundry, mopping, goal planning, learning, applications and customer outreach. Presets do not write the calendar until reviewed and saved. The existing day window and flexible percentage limit apply; protect all existing placements while adding sessions. Preview every occurrence. If a day has no room, retain an untimed flexible task clearly marked as needing room. Existing daily observation can place it later. No LLM is needed.

Persist the definition and occurrence links transactionally. A preview is invalid after any calendar revision or planning-setting change and must be regenerated; repeated Save does not duplicate a routine. Individual sessions remain editable. Stopping a routine removes only future, incomplete, unedited sessions; preserve past, completed or manually edited entries. Reconcile native alarms after mutations. Initial creation is reported in the routine list and supports stopping/removing its upcoming sessions; existing change-report Undo continues for automatic rearrangements.

Daily progress counts tasks by scheduled date, excluding events. Completed wins; an incomplete timed task becomes missed after its full duration ends; an untimed task becomes missed after its date ends. Late completion turns that task green. Empty days have no fabricated success/failure. Keep existing activity totals/streaks based on actual completion date, and label the distinction. Tap any heatmap day to inspect its timeline. Chat creation confirmations gain a direct timeline link so future entries are easy to find.

Builder choices: use an explicit form and preview for recurring work in this release; arbitrary recurring natural-language tool parsing and automatic book chapter division remain future work. Ringing stays the existing user opt-in. The calendar remains Anchor-owned; there is no phone-calendar synchronization. Tests use disposable data; do not seed personal routines without a Save action.
