# Conversation-driven period plans

The user wants whole task lists organised into daily essentials and longer challenge goals, saved as a coherent routine, with conversation-driven additions and rescheduling. Their November–December interests are self-development/countries/health reading, organising their library, daily rest, hackathons, research and occasional dated events; household chores were specified earlier. They already chose automatic gap placement with manual adjustment. November1–December31,2026 is61 days. Do not invent event dates, work deadlines, book chapters or saved personal commitments.

Keep the existing offline Java/SQLite/llama.cpp app. Add a period-plan composer accepting a list of bounded routine definitions. Each definition has category daily/challenge, title, session minutes and selected weekdays; one shared date range1–90days. Default suggestions are editable, clearly identified as suggestions and never saved until reviewed. Daily essentials are allocated first, then challenges, preserving relative order in each group. Existing appointments and task placements remain protected. Preview every occurrence; retain no-room entries visibly and preserve reminder intent. Save the entire batch atomically against one calendar revision and planning-settings snapshot; persist a plan summary and guarded Undo for the created batch. No model output writes directly.

Model plan extraction uses a compact, validated proposal schema, at most12 items. Scheduling is deterministic; the model only suggests titles/categories/durations/weekdays. A compact dedicated on-demand call stays within the existing1024-token runtime context and uses up to384 output tokens. Parsing/cancellation failure returns a usable editable list workflow, never JSON. Existing single-task chat behaviour remains. Provide deterministic editable fallback when no model is available. Context exposes bounded upcoming task IDs and active routine summaries when relevant, with explicit truncation.

Explicit move/reschedule requests open a selection/review flow for an exact existing task. A request must not silently choose among recurring occurrences. Let the user choose the session and new date/time; show the old and proposed placement. Respect protected entries, reject collisions/stale edits/past placements/completed tasks, save a durable change report and existing Undo. Only movable flexible tasks are eligible for this agent move; protected commitments remain editable from their own timeline entry. Whole-series edits and free-form per-goal chapter/deadline reasoning remain future scope.

Builder defaults: reading30min rotating topics across the week, library45min weekly, rest45min daily, hackathon60min weekdays, research45min3days/week; optional chores templates from the earlier request. These are suggestions, not an agreed personal schedule. Plan UI supports exact start/end dates and the November–December61-day shortcut. Ringing remains the existing explicit user setting; alarms and observation remain independent of inference. Existing60-day consistency view stays60 days; the period plan may span61 days.
