# Anchor Implementation Plan

> **For agentic workers:** use parallel focused implementers and a fresh final review. Execute the user's authorized build request without another approval gate.

**Goal:** Deliver a useful offline Android planner and an honest on-device AI feasibility path.

**Architecture:** Framework-native Java UI over app-private SQLite. AlarmManager handles reminders; JNI llama.cpp handles manually imported GGUF models, separate from planner lifecycle.

**Tech Stack:** Java17 bytecode, Android36, SQLiteOpenHelper, llama.cpp C++/NDK, local Android speech.

**Spec:** ../specs/2026-10-28-anchor-design.md

## Global constraints

- No INTERNET permission or Google Calendar integration. No fabricated history or benchmark values.
- Minimum API26; actual HONOR compatibility and model feasibility require device checks.
- All user writes survive restarts; all chat/memory deletion is explicit.

## Review focus

- Local dates across month/year/DST/timezone changes and completion undo.
- Stale reminder intents after edit, completion or deletion; reboot and denied permissions.
- Missing/corrupt/oversized models, context overflow, cancel/unload and lifecycle.
- Unsupported on-device STT/TTS must not invoke a network fallback.
- Empty database, long text, keyboard input and accessibility touch targets.

### Task 1: Domain, persistence and alarms (root)
- [ ] Write domain tests for leap days, bad time/date, duration, local completion/streak and reminder instant. Run RED, implement, run GREEN.
- [ ] Implement shared DTOs and AnchorDb schema, parameterized CRUD, explicit memories/chat; add device persistence tests.
- [ ] Implement reminders with cancellation/reconciliation and boot/time change receivers; device tests cover edited/deleted/completed rows.

### Task 2: Native user interface (UI implementer)
- [ ] Read spec's shared interfaces; implement Today timeline, month navigation, task/event add/edit/delete/check/undo, progress heatmap, memory settings, accessible bottom navigation.
- [ ] Connect every control to real data; validate form input, preserve state through tab changes, render empty states. No demo data.
- [ ] Leave AI callbacks via LocalAi contract agreed with root. Verify compilation and UI behavior.

### Task 3: Local inference and voice (AI implementer)
- [ ] Verify official Granite model, runtime support/license, alternatives and exact file sizes using primary sources.
- [ ] Implement JNI model load/unload/generation, bounded context and explicit cancellation; import into private storage.
- [ ] Implement real benchmark measurements and on-device-only speech availability checks. Test invalid GGUF and unavailable speech paths.

### Task 4: Integrate and deliver (root + fresh reviewer)
- [ ] Build APK and inspect permissions; run whole JVM/device suite.
- [ ] Exercise UI and offline persistence on connected device/emulator. Measure actual model when phone authorized; record blockers otherwise.
- [ ] Fresh review for correctness/privacy; fix material issues and repeat affected checks.
- [ ] Provide APK/source archive, installation instructions, research/validation report with accurate remaining limits.
